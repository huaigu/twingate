# Two-person SignalPass pilot

**Status: prepared, not completed.** No participants have been recruited or contacted by this guide. The existing [public rehearsal](reports/signalpass-public-journey-2026-10-03.md) used fictional accounts; this pilot is for two real people deciding whether an introduction is useful.

Aim for one 15–20 minute session. Use a real shared interest or complementary need, two independently controlled wallets and the [live product](https://signalpass.coderbojack.space/assistant?demo=0). Start with **Send without a bond**: no payment, MON funding or chain transaction is needed. SignalPass covers the included hosted AI requests. Sign-in requires a wallet message signature, not a transaction; never share a seed phrase or private key.

## Invitation draft — not sent

> Would you like to try SignalPass with one other person for about 15–20 minutes? It helps you find a reason to connect, review an AI-assisted introduction and choose whether to reply. Participation is optional, and there is no obligation to accept an introduction or share contact details.
>
> You approve your own profile. To be discoverable, you must explicitly make it public and enable matching; the sender can keep their own profile private. The hosted AI provider, currently TokenRhythm, receives your goal and relevant public profile fields; using your own approved profile also requires consent. Please use only information you are comfortable sharing this way.
>
> We will use the no-bond option, with no payment required. If you agree, we would like brief feedback on usefulness and control. Screenshots, quotes or public write-ups need your separate permission. You can stop and turn matching off at any time.

## Before starting

- Both people agree to participate and know who is running the session. Each controls their own wallet, browser session and decisions. The facilitator never signs or sends on anyone's behalf.
- Each person approves an accurate profile. The **recipient** explicitly chooses **Public**, enables matching and is open to introductions. The sender's profile may remain private. Do not create profiles for other people or reuse fictional QA accounts as participants.
- Explain model input: the goal, clarification answers and a minimal profile projection—handle, display name, building, can offer, wants to meet and interests. The sender's approved profile needs explicit AI-use consent, and drafting requires it. Public matching profiles can be considered as candidates. Wallet addresses, imported source links, private source text, inbox messages and contact channels are not automatically included; do not paste private information into the goal or profile fields. [Full data and consent boundaries](HOSTED_AGENT.md#data-and-consent).
- Open live mode using the link above; `?demo=1` is an offline fictional walkthrough. Confirm the hosted agent is available with included requests remaining. An empty eligible pool or provider error is a valid finding, not a reason to substitute a sample result.
- Agree to short private feedback notes. Use participant labels in notes; omit wallet addresses, private messages and contact details. Obtain separate permission before recording the screen or publishing any identifiable result.

## Two-role script

| Step | Sender | Recipient / observation |
| --- | --- | --- |
| 1. A real goal | Enter what you actually want help with or who you want to meet. Choose whether the agent may use your approved profile. | Confirm your published profile accurately describes what you offer and what interests you. |
| 2. Assess the suggestion | Read the reason, caveat and source quote. Rate relevance **1–5** before editing anything: 1 = unrelated, 3 = plausible, 5 = directly useful. Answer a clarification only if one is offered. | Check that quoted facts match your published profile. With only two participants, this tests usefulness and consent, not ranking at scale. No match is an acceptable result. |
| 3. Prepare a private draft | Explicitly permit profile use for drafting. Review every personal claim, correct unsupported wording and edit the proposed next step. Open the composer and decide what profile context to share. | Confirm that no introduction appears in your inbox while the sender is still drafting. |
| 4. Confirm delivery | Review the exact final text in the separate send dialog and choose **Send without a bond**. Send only if you want this person to receive it. If a payment/transaction request appears, stop and recheck the chosen option. | Open your own inbox after the send. Compare the delivered text with what the sender approved, with both people's permission; record **same / different**, without copying private text into the notes. |
| 5. Make a real choice | Wait for the recipient's decision. If they ask for context, review and explicitly send any reply. | Before deciding, answer: **Would I reply outside this test: yes / maybe / no?** Then freely accept, ask for context or decline. Acceptance is not a condition of a successful session. |
| 6. Optional next step | If accepted, decide whether to preview and share one contact or scheduling channel. Sharing is optional. | Make your own separate choice. Check that acceptance alone revealed no contact details and only the explicitly confirmed channel is visible to the other participant. Refresh to check the observed state persists. |

If discovery finds no useful fit, the model fails or either person declines consent, record where the session stopped. Do not force a match, invent familiarity or count a manual/sample fallback as a completed AI journey. Keep real observations separate from the earlier fictional rehearsal.

## Feedback template

Copy this into private session notes, not the public repository. Leave unavailable results as **not observed**.

```text
Session date / duration:
Participant labels (no wallet addresses):
Both agreed to participate and private feedback notes: yes / no
Recipient explicitly chose public profile + matching: yes / no
Sender explicitly approved AI profile use before drafting: yes / no
Goal, summarized without private details:
Suggestion relevance: 1 / 2 / 3 / 4 / 5 / no suggestion
Source quote accurate: yes / no / not observed
Draft needed factual corrections: none / minor / major (brief reason)
Delivered exactly the approved message: yes / no / not observed
Recipient would reply outside this test: yes / maybe / no
Actual decision: accepted / asked for context / declined / not sent
Contact sharing: not offered / declined / explicitly approved by each sharer
Any unexpected contact disclosure: yes / no / not observed
What felt useful? What felt confusing or uncomfortable?
Did either person choose a next conversation? (Do not infer from acceptance.)
Cleanup completed by each participant:
Permission to use a de-identified summary or quote: none / exact agreed scope
```

The first result is a case study of two people, not a growth metric or recommendation benchmark. Report the number of consenting participants, actual decisions and observed limits; do not turn planned participation into traction.

## Finish and clean up

Each participant chooses whether to stay discoverable. If they do not want to remain in the pilot, turn matching off and set the profile to private. Remove any shared contact channel through the accepted receipt if desired, clear hosted-agent history and sign out. Confirm these choices separately with each person.

Clearing AI history does not erase sent introductions or reset usage. Removing a contact stops future reads but cannot recall a copy the other person already made. Do not promise complete deletion or provider non-retention; [the data guide](HOSTED_AGENT.md#data-and-consent) describes those boundaries. Retain only the agreed feedback notes and record any cleanup that could not be confirmed.
