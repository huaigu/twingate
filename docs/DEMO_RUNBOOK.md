# SignalPass 评审演示脚本

## 演示前准备

先运行 pnpm verify:all。当前本地版本运行 pnpm chain:dev，地址为 http://localhost:3005/；明确展示 Local EVM / DEV，不说成 Monad 测试网。若已完成公开测试网部署，按 docs/WALLET_BONDS.md 运行 preflight，再使用该部署。

准备两只独立钱包和两份真实批准的资料。收件人公开或限链接可见，并已在 My agent 中完成资料/政策同步。两只钱包都需要对应网络的 gas；本地演示可以使用 Add local test balance。

介绍文本应是一项具体协作邀请：你正在做什么、为何找这个人、能贡献什么、下一步是什么。避免使用捏造的过往贡献、共同关系或链上成绩。先把两页开在各自的浏览器会话里，再开始计时。

## 约 90 秒主线

| 时间 | 屏幕操作 | 讲述重点 |
| --- | --- | --- |
| 0–15 秒 | 展示接收方资料与可合作方向 | “陌生私信缺少判断依据。这里先把协作意图说清楚，对方仍然决定要不要回应。” |
| 15–30 秒 | 发送方审阅四段介绍与共享上下文，选择钱包保证金 | “发送前确认披露内容。这次使用人工审核，AI 费用为零。” |
| 30–45 秒 | 展示报价与退款规则，确认钱包交易 | “保证金是临时锁定。接受、拒绝或超时领取都会退给发送人，gas 单独支付。” |
| 45–60 秒 | 回执显示确认区块；切到收件箱 | “只有链上确认以后，对方才收到这封介绍。” |
| 60–75 秒 | 收件人接受，确认钱包；也可选择拒绝作为备选演示 | “接收方拥有决定权，系统不替人做关系判断。” |
| 75–90 秒 | 返回发送方回执，展示实际退款金额与交易 | “关系是否继续由人决定，资金结算可以逐笔核对。” |

本地链没有公网浏览器时，展示完整交易哈希、确认区块及退款金额。公开测试网演示再打开已验证的 explorer 链接。不要用本地哈希暗示公网部署。

## 备选流程与故障处理

- **想看拒绝**：再发一封介绍，收件人拒绝；展示同样完整的保证金退款。
- **想看超时**：本地响应期是 60 秒。截止后参与者在回执点 Claim expired bond；测试网使用资料政策的实际时限。
- **钱包取消**：明确显示取消，没有新的广播交易；可以重新审核后确认。
- **浏览器刷新/回调丢失**：保留原回执，等自动对账恢复；不要立刻重复付款。
- **报价不可用**：确认接收方已同步资料和政策；修改政策后重新审核一封介绍。
- **公网 RPC 不可用**：停在上次确认状态，说明链连接问题。若切换本地演示，要直接指出网络变更。

## 收尾回答

已经验证的是有真实钱包授权、有实际链上锁仓和退款、有双方隐私边界的介绍流程。尚未启用的 Hunyuan、自动匹配、第三方信号和嵌入式钱包不应出现在“已完成”演示清单里。

后续产品验证看用户是否更容易判断“值不值得开始一次对话”，以及保证金与退款是否容易理解。不要以动画数量或演示中的虚构成功率作为价值证明。
