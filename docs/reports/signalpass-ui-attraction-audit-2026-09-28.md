# SignalPass：吸引力与 UI 方向诊断

日期：2026-09-28。范围：当前 3005 预览、当前工作区与 1440×900 桌面测量。

## 判断

当前产品已有可识别的纸张、人物与编辑式排版，但注意力分配还没有围绕产品最有价值的时刻组织起来。大标题、拼贴和抽象的连接叙事占据主要位置，人物的具体价值、建立联系的依据和核心操作相对弱。

前几轮修复提高了可用性、一致性和操作反馈；它们没有充分解决首屏叙事、工作区比例和产品记忆点。这解释了为什么对齐和动画补齐后，仍然会觉得吸引力不足。

## 建议保留的方向

保留纸张、人物和信件的温度，把主要画面让给具体的人、可核实的共同背景和一封可审阅的介绍。

- 领域：介绍、往来、共同背景、合作互补、双方同意、公开资料、可退款承诺。
- 色彩：米色纸张、象牙白阅读面、深墨色正文、紫色操作、淡紫辅助、鼠尾草绿接受状态。
- 核心视觉线索：一条带有具体依据的连接——我能提供什么、对方在寻找什么、准备如何开口、哪些内容经双方同意。
- 减少的默认做法：每页重复大标题和大插画；所有人物等权的通用卡片；以漂浮和倾斜作为主要记忆点。
- 对应替代：按任务组织的工作区；人物与合作依据的明确主次；沿着实际介绍状态变化的反馈。

介绍预览已存在，不应把同样的两个头像和共同兴趣重新包装成新功能。真正的变化应是把它提前、放大，并让它承载更具体的信息和持续的交互。

## 下一轮应该做什么

### 1. 首页：让人迅速看懂一次具体的连接

- 主标题明确面向谁、帮助完成什么；例如围绕寻找可以一起做事的人，而不仅是抽象的更多可能。
- 用一个可展开的具体介绍场景承载主要视觉：两位人物、获准的背景、合作依据、一封可预览的介绍。
- 以一个体验价值的主要行动组织首屏；登录状态收敛为导航中的账户入口或紧凑状态，不压过产品内容。
- 涉及发送、共享资料、费用和钱包授权时，在相关动作附近充分展示事实。

### 2. 发现页：让“为什么值得认识”成为主内容

- 缩小重复的宣传标题和装饰，让人物与资料获得更大的阅读空间。
- 增强当前选中人物的详情和连接依据；展示公开资料中确实存在的共同兴趣、需求和可提供的帮助。
- 不引入没有依据的匹配分数或 AI 排名。Hunyuan 继续保持未配置，真实模式按当前能力表达。
- 对当前内容不足的问题，提供明显标注的示例体验，并逐步引入经授权的真实公开资料；示例人物不计为真实用户。

### 3. 写信与接受：形成一个连续、完整的场景

- 以可读的信件编辑区为中心，人物与共享上下文作为辅助信息。
- 统一正文、标签、编辑入口和费用说明的尺度，逐项处理小字号和小控件。
- 动效跟随用户选入资料、审阅、发送和对方实际接受的状态变化；仅在状态确实成立时出现结果反馈。
- 明确接受后的下一步，让完成一次介绍本身有可感知的结果。

### 4. 把三屏的决定沉淀到共享系统

- 先确定首页、发现、写信三屏的主次与比例，再扩展到其余页面。
- 将工作区逐步调整为正常响应式布局，装饰与交互内容分层管理。
- 统一字号、容器、按钮、状态、导航与阅读表面的组件规范，减少页面专用覆盖。

## 评价下一版的方法

以下是拟定的验收目标，尚未执行用户测试：

1. 首次看到页面的人能用一句话说出产品帮助谁、解决什么问题。
2. 每个核心页面都有唯一清晰的主要行动。
3. 用户能从实际资料指出一条建立联系的具体依据。
4. 无需口头引导即可找到资料编辑、共享内容审阅和介绍确认入口。
5. 演示、真实用户、自动建议和人工决定的界限清楚。
6. 页面截图和实际操作均检查；构建通过及 DOM 对齐不能代替视觉验收。

## 检查边界与证据

本次读取了实时首页、实时发现页，以及明确示例模式的发现、资料和写信页；记录保存在 .run/ui-attraction-audit/observations.json，同目录有对应截图。没有修改产品界面。

当前环境不支持图片输入，本次判断来自页面实际内容、DOM 几何、计算后样式和现有设计实现；并未直接审读截图像素。因此上述是有页面证据的结构与体验诊断，不是逐像素视觉评分。下一轮应以可比较的设计方案和人工可审阅的页面效果进一步验证。
