# SignalPass 阶段报告：真实钱包闭环

日期：2026-09-28。执行依据：Hunyuan 暂不配置，其余按先前优先级继续。

## 现在完成到哪里

介绍流程已经从持久化的双方交流，推进到真实本地 EVM 上的「签名报价 → 用户钱包锁定 → 收件人处理 → 保证金退款」。网页、API、合约之间的资金状态来自实际交易和事件，浏览器状态不能伪造付款。

当前可查看的链上版本运行在 **http://localhost:3005/**。网络明确显示 **Local EVM / DEV**。原有 **3004** 无付款版本和数据保持独立。Hunyuan 未配置；本阶段采用人工审核，AI 评估费为零。

这证明了机制可运行，还不是已完成公开 Monad 测试网部署，也不能据此承诺获奖。

## 本次交付

| 用户场景 | 现在的行为 | 验证方式 |
| --- | --- | --- |
| 钱包注册资料 | 人工批准资料后，登记内容哈希与政策哈希；原文留在应用内 | 浏览器发起真实本地 EVM 交易 |
| 审核付款 | 展示实际金额、零 AI 费、独立 gas、报价有效期和退款条件 | 浏览器取消后没有广播新交易 |
| 发送介绍 | 先创建待付款草稿；验证锁仓交易后才向收件人投递 | 未付款时收件人列表和详情不可见 |
| 内容绑定 | 报价绑定应用记录、双方钱包、资料/政策版本、原消息哈希、金额和有效期 | viem 的 EIP-712 摘要与 Solidity 完全相同 |
| 交易防伪 | 校验网络、合约、调用数据、金额、发送人、规范区块与事件 | 篡改金额、重放、无关交易、伪造接受均被拒绝 |
| 补充上下文 | 双方可继续问答；补充内容不冒充原始链上承诺 | 两浏览器问答与 payload 哈希不变断言 |
| 接受/拒绝 | 收件人钱包确认；合约把全部保证金退给发送人 | 交易事件和余额增量核对，单独扣除 gas |
| 超时 | 截止后由参与者发起退款；到期前拒绝伪造超时 | API 与浏览器均验证 |
| 中断恢复 | 丢失浏览器回调后，从链上日志找到锁仓；重启 API 后保留会话和结果 | 实际省略回调并重启进程 |
| 本地开发 | 一条 pnpm chain:dev 启动持久化链、API、页面；钱包密钥留在受保护文件 | 完整停止、启动后合约地址和 signer 检查一致 |

## 下一步顺序

### 1. 补齐公开 Monad 测试网证据

部署脚本已支持独立报价 signer 和 treasury，并限制为本地链或测试网。清单模板和只读 preflight 已就绪。下一项需要本机准备有测试币的部署钱包；私钥不要发到对话里。

完成标准：用两个独立钱包在公开测试网上完成资料登记、锁仓、接受和退款；保存可核查的合约地址、交易哈希与浏览器链接。旧版无签名 lock ABI 不应复用，需部署当前版本。

### 2. 形成可复现的评审演示

演示脚本已放在 docs/DEMO_RUNBOOK.md。主线是「一封有上下文的介绍，如何获得对方注意，同时保留对方拒绝的自由」。金额和退款证据由钱包及回执直接展示；本地链、示例模式、人工审核都明确说明。

### 3. 用真实试用验证价值

下一轮找 6–10 位目标用户，在不口头代操作的情况下完成介绍和回应。记录：首次完成耗时、报价理解错误、钱包中断点、接受/拒绝后是否理解钱回给谁。优先消除误解与卡点，再扩充自动发现、第三方信号或 AI 能力。此处人数是试用计划，不是已有用户数据。

## 当前边界

Hunyuan、自动 AI 匹配、第三方身份/信号验证仍未启用。Dynamic 嵌入式钱包尚未接入，当前使用注入式 EOA 钱包。Envio 公开索引未部署，当前通过 API 的 RPC 对账恢复状态。手动审核路径使用 escrow 事件作为结算证明，没有伪造 AI 评估凭证。当前数据库支持单 API 写进程。

仓库已有大量未提交设计与页面修改，本轮保留这些工作，没有替用户执行整体提交或公开部署。
