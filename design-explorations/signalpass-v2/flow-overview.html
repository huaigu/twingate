declined这一次介绍，到这里结束。不解锁私密空间 · 按公开规则结算 Bond
点击Decline introduction → 明确的终态

Bob 谢绝的是这一张介绍。给 Alice 清晰的状态并处理 Bond；无需把拒绝包装成“已收藏”。此分支不是 Hero 的 Later / Undo。

当前 Inbox 的 Decline 已存在。若今后支持暂缓“已经收到的请求”，它仍是未决请求，不能无限延长资金占用或原超时窗口。

评估建议不是人的判断。当前 Agent 的 not_now 建议也不会自动决定 declined；设计上的“接受 / 追问 / 谢绝”必须由接收者主动选择。

BACK TO THE HERO

首页那两个按钮，放回整个流程里看。

Hero 展示的是一个快捷示例。V2 将它理解为 Alice 在预览“还未发送的候选与草稿”，不要和 Bob 在真实收件箱里的接受行为混淆。

Your call · Alice 预览

“我想看看，怎么介绍自己。”

Your call → 草稿审阅 → 编辑 / 确认报价 → Approve and send

目标动效是纸卡抬起、审阅抽屉展开。打开抽屉不算发送；更不代表 Bob 已经接受。当前 Web 按钮会直接去 Composer，抽屉仍是设计目标。

Not now · 未发送的候选

“先收起来，之后再考虑。”

Not now → Save for later → Undo 可恢复候选

目标动效是卡片折叠收进 Later。它不发消息、不支付、不产生拒绝记录。当前 Hero 仅有 toast，图中的持久化收藏与 Undo 尚未实现。
